# Требования и этапы

Источник: «ТЗ_Курс_ТП.pdf», страницы 2–3, предоставленное командой 20 октября 2026 года. Название: «Разработка интеллектуальной системы управления задачами с автоматизацией цикла разработки через GitHub и LLM-агентов». Репозиторий в ТЗ: `https://github.com/Soniap06/task-manager.git`.

Ниже — рабочее изложение для общего контекста в git; исходный PDF остаётся первичным документом. PDF не копируется с личного компьютера и не нужен для повседневного запуска. ID и порядок этапов введены для разработки, в оригинале их нет. Статусы синхронизированы 21 октября 2026 года с рабочей веткой `codex/ui-sofia-style` (`7cf4c7a`), опубликованной в origin; это не утверждение о merge в main. Подробности текущей реализации и ограничения — в [PROJECT.md](PROJECT.md).

Входы из ТЗ: описания бэклога и предметной области, профили участников, webhook-события `push`, `pull_request`, `pull_request_review`. Выходы: доска, планировщик, сервис веток/PR, review с публикацией комментариев, записка и исходники.

## Уточнение пользователя: подключаемые проекты (20 октября 2026)

Расширение R4, обозначение **R4-PROJECTS**: Task Manager подключается к существующим GitHub-репозиториям и позволяет менять рабочий проект через интерфейс. Нужны выбор из доступных репозиториев, подключение по GitHub-ссылке, отдельная доска каждого проекта и неизменность привязки созданной задачи к исходному репозиторию. Роли пока не учитываются. Это запрос пользователя сверх исходного ТЗ; подключение проектов реализовано в текущих изменениях по [обновлённому плану](plans/R4-create-task-branch.md). Загрузка ZIP не входит в первую версию: она не предоставляет доступа для создания GitHub-веток.

## Дальнейшие этапы с учётом готовой основы

Это бэклог для выбора отдельных задач, а не команда агенту выполнять его целиком.

1. **Основа — реализована для локального запуска.** Общий серверный LLM-клиент, отдельный локальный конфиг, проверяемый контракт черновика, ограниченная раздача файлов и тесты с заглушками уже есть. Перед публичным размещением отдельно спроектировать права пользователей и общее хранение.
2. **Доска и данные (R1, DATA).** Дополнить три статуса до пяти и добавить редактирование подтверждённых карточек. Сохранность уже обеспечена JSON v2; отдельно спроектировать перенос рабочих задач/проектов в SQLite с резервной копией и сохранением данных GitHub/генерации. Сохранность при перезагрузке — инженерный критерий, явно не описанный в ТЗ.
3. **Команда и спринт (R2–R3).** На основе существующих страниц сотрудников/профиля добавить редактирование, оценки часов, спринт и планирование. Ограничения проверяются кодом, а не только промптом. Отсутствующие компетенции и превышение нагрузки имеют явный результат.
4. **GitHub App (R4).** Подключение проектов, серверная аутентификация App, ветки, проверка подписи webhook и дедупликация уже реализованы. Следующий объём — создание PR при Review, хранение связи задача/ветка/PR и настройка с проверкой реальной доставки webhook. Изменение колонки сейчас само по себе PR не создаёт.
5. **Автоматическое review (R5).** Получение актуального diff, структурированный результат LLM, привязка к строкам и публикация; защита от устаревших и повторных комментариев.
6. **AI-исполнитель (R6).** Ограниченная область файлов и задач, изолированное выполнение, diff и проверки до применения результата.
7. **Защита (R7).** Записка и демонстрационный сценарий с проверкой работы всех модулей; материалы собирать по мере разработки.

Проверка webhook, повторов, секретов и валидация LLM — предложенные инженерные условия надёжности, а не дословные пункты ТЗ. Детальные критерии и распределение ответственности фиксируются в конкретной задаче/плане.

## DATA-1.1: подготовка БД (запрос пользователя)

SQLite, таблицы users/projects/employees/tasks/events, ограничения и FK tasks.assignee_id → employees.id подготовлены отдельно. Скрипт инициализации повторяем и проверен тестами. Изначально по запросу «пока просто создай» была подготовлена только схема. При последующей интеграции Софии сотрудники и события подключены к UI/API, проекты зеркалируются в SQLite для FK событий; добавлена дедупликация webhook. Рабочие задачи и проекты остаются в JSON v2; перенос задач в SQLite и операции изменения сотрудников/пользователей ещё предстоят. [Схема](DATABASE.md), [план и DoD](plans/DATA-1.1.md).
