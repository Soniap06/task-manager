## Реализовано

Создание задачи инициирует серверную генерацию описания и реальную ветку через GitHub App. Ветка получает UUID задачи и slug модели, создаётся от сохранённого SHA базовой ветки. UI показывает ссылку только после подтверждения в окне задачи. На доске карточки свёрнуты до названия и кнопок переноса; подробности открываются нажатием на карточку. Генерация и GitHub имеют отдельные состояния ошибок и возможность повтора. Карточки и колонки хранятся в `.data/tasks.json` и восстанавливаются при перезагрузке.

Повтор с тем же request ID не создаёт новую задачу. При потерянном ответе GitHub проверяется точный ref. При перезапуске сервер сверяет незавершённые попытки, дошедшие до GitHub. Чужие и изменённые ветки не перезаписываются, локальный checkout не переключается. Публичные файлы ограничены HTML/CSS/JS интерфейса; секреты и данные не раздаются, CORS `*` удалён.

GitHub App имеет доступ к `karinalien/habit-tracker` и ранее разрешённому репозиторию исходников `karinalien/task-manager`. Первый рабочий подключённый проект — трекер привычек; новые ветки для него создаются в отдельном репозитории.

Реализованы каталог доступных App репозиториев, подключение по ссылке/списку, выбор базы, отдельные доски, смена проекта и локальное архивирование подключения. Снимок repository/installation/base хранится у каждой задачи; ID проекта передаётся явно. Токены записи ограничены repository ID, кэш разделён по scope. Текущий формат JSON — версия 2, миграция версии 1 сохраняет резервную копию и не угадывает проект старых задач.

Подготовлена отдельная SQLite `.data/task-manager.sqlite` с users/projects/employees/tasks/events и скриптом `npm run db:init`. Она пока не подключена к API, работающий store остаётся JSON. [Схема и ограничения](DATABASE.md).

## Ограничения и следующие задачи

- Нет Backlog и Done, редактирования карточек, профилей, сущности спринта и алгоритма распределения.
- Нет создания PR, webhook-событий, автоматического review и AI-исполнителя.
- Локальный JSON и однопроцессная очередь подходят текущему запуску; это не общая БД команды. Доски разных локальных серверов независимы.
- Нет пользовательской авторизации: сервер слушает только loopback. Перед публичным размещением нужны аутентификация, права пользователей и общая стратегия хранения.
- После аварии генерация без сохранённого результата требует явного повтора. При конфликте существующей ветки требуется ручной разбор; автоматического удаления или переименования веток нет.
- В `.env` хранятся настройки App/LM Studio; рабочие repo/base выбираются в интерфейсе. Личный `ai-api.js` сохранён, но не исполняется; документация прежнего клиента не описывает текущий запуск.
- Модель должна быть запущена в LM Studio; отказ модели не теряет сохранённую карточку. Генерация ограничена 120 секундами, GitHub-запросы — 15 секундами каждый.
- Автоматические тесты используют заглушки. Реальные проверки и их ограничения фиксируются в плане R4.
