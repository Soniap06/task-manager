# R3: профиль генерации Qwen

7 ноября 2026. Ветка codex/r3-qwen-inference-profile от upstream/main 4bde48f. Статус: сравнение профилей на локальной модели; без публикации и развёртывания.

Цель: проверить рекомендации авторов Qwen3.5-9B на задачах Task Manager, не обещая универсального оптимума. Источник: https://huggingface.co/Qwen/Qwen3.5-9B (Instruct mode и Best Practices).

Проверить старый профиль и рекомендуемый non-thinking: temperature=0.7, top_p=0.8, top_k=20, min_p=0, presence_penalty=1.5, repetition_penalty=1.0 (LM Studio: repeat_penalty). Отключение thinking через chat_template_kwargs.enable_thinking=false требует проверки именно установленной LM Studio. Сохранить контекст 32768, parallel=1 и timeout 300000; не увеличивать контекст до максимума модели на Mac 16 ГБ.

Проверки: обычный черновик с 404/тестами, первая пачка интервью, CSV с попыткой нарушить формат, английский slug. Только createLlm: без TaskService, БД, карточек и GitHub. Сравнить контракт, смысл, время и наличие reasoning_content. Дополнить автоматические проверки конфигурации при изменении допустимых параметров. Личные настройки менять адресно с резервной копией; серверный выпуск отдельно.

## Наблюдения

Установлена Qwen3.5-9B MLX 4bit (~5.98 ГБ), контекст 32768, parallel=1. До проверки модель была выгружена. Загружена через lms. Изменения model.yaml обратимы: рядом сохранён model.yaml.before-task-manager-20261107; обновление модели из Hub может сбросить настройки. Личный конфиг основного checkout сохранён как ai.config.json.before-hf-20261107, endpoint/model/apiKeyEnv не менялись. Старый валидатор проекта не принимает новый min_p, поэтому в прежний личный конфиг это поле не добавлялось; в LM Studio min-p отключён, что соответствует нулю.

В установленной LM Studio chat_template_kwargs.enable_thinking=false принимался, но reasoning_content оставался. Через customFields.enableThinking.defaultValue в model.yaml и перезагрузку отключение подтверждено API и отсутствием reasoning_content. Этот профиль отклонён по смысловой проверке; thinking возвращён.

Обычные ответы non-thinking: удаление 45.7 с (пропущены тесты), категории 65.8 с (придуманы поля и ограничения), CSV 33.8 с (перенесён служебный запрет Markdown в описание), slug 5.9 с (корректен). Контракт проходил 4/4, смысл — с замечаниями. Это один прогон, без статистики; время старого профиля измерялось на немного иных запросах/прогретом кэше, ускорение не доказано. Первичная попытка grilling в сравнительном скрипте использовала ошибочный boolean вместо объекта бюджета, HTTP 400 исключён из оценки модели; повторная проверка использовала реальный бюджет minimum/maximum/answered.

Для точного режима выбраны temperature=0.6, top_p=0.95, top_k=20, min_p=0, presence_penalty=0, repeat_penalty=1, thinking включён. Исходные 0.1/0.8/0/1.05 доступны в резервной копии. max_tokens=1600 и timeoutMs=300000 сохранены как ограничение приложения, а не максимальные значения из карточки Qwen.

Серверные файлы, firewall, GitHub и данные не менялись. Результаты генераций — только временные файлы /private/tmp, не репозиторий. Семантическое качество вопросов/описания остаётся отдельной открытой задачей; изменение sampling не заменяет её.

## Продолжение R3: качество карточек

По поручению пользователя 7 ноября работа в этой незавершённой R3-ветке продолжена: настройка sampling оказалась недостаточной. Коммита настройки ещё нет; изменения сохранены, сервер не обновляется.

Реализованы дополнительные инструкции о неподтверждённых ответах и недоверии к прежнему draft, технический шаблон «какое поле отвечает», правила повторов по ограниченным темам (неизвестный ID, авторизация, импорт, поиск, кратность/уникальность категории). Последние сравнивают вопросы с отвеченными вопросами и отдельными явными исходными условиями; «не знаю/не определено» не закрывает тему. Формат сообщения об ошибке отделён от уже известного кода ошибки.

lib/draft-quality.js также проверяет некоторые неподтверждённые утверждения описания (отдельная страница/список результатов, уникальность имени, флаг активности, HTTP-коды) и потерю исходных требований тестов/ошибок. Источники фактов — input и answers, не старый draft и не предлагающий вариант вопрос. Эти проверки действуют в новом grilling-пути, включая финализацию; старый режим 0–3 и slug-контракт не менялись.

Одна общая корректирующая генерация применяется к вопросам и описанию в пределах прежнего deadline. Второй неуспех оставляет generation_error и сохранённые ответы; автоподтверждения и дополнительных GitHub-записей нет.

Границы: это консервативные предметные правила для воспроизведённых ошибок, а не универсальный семантический судья. Они не доказывают отсутствие любых новых условий/парафразов и могут отклонить допустимое уточнение той же темы. Минимум 9 вопросов по прежнему требованию сохранён, поэтому узкие задачи могут остановиться вместо получения новых надуманных вопросов. Человеческая проверка обязательна. Нерелевантные тестовые ответы не считаются полноценной пользовательской приёмкой.
