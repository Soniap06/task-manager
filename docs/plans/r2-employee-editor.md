# R2: интерфейс управления сотрудниками

Статус: реализовано локально, ожидает визуальной приёмки. Владелец: Карина. Review: София.
Ветка: `r2-employee-editor`, база `01aa937227c6` (main).

## Результат и границы

Создание и редактирование сотрудников на /team через существующие POST/PATCH API.
Поля: имя, должность из списка, отдельный грейд, группы компетенций,
технологии из общего справочника, часы за спринт и файл аватара.
Тип исполнителя выбирается по должности «ИИ-ассистент»; старый тип сохраняется при неизменной прежней должности.
Без удаления сотрудников, учётных записей, назначения прав, автоматического планировщика и публикации на VPS.
Сотрудники общие для рабочего пространства; счётчик задач относится к выбранному проекту.

## Критерии и проверки

- Добавление, редактирование и отмена; новый сотрудник остаётся после перезагрузки.
- PATCH отправляет только изменённые поля и сохраняет ID/назначения.
- Ошибки сохраняют ввод; повторное нажатие во время запроса не дублирует запись.
- Доступность: подписи, модальный диалог, Escape, возврат фокуса; мобильная ширина.
- Безопасный текст и аватар с запасными инициалами.
- npm test, npm run check, git diff --check; отдельная UI-проверка на временных данных.

## Ограничения

API не поддерживает версии сотрудника: параллельное редактирование одного и того же поля
остаётся last-write-wins. Отправка только изменённых полей сохраняет чужие изменения остальных полей.

## Уточнение после согласования 18 ноября

- Должности и технологии согласованы с Кариной. Справочник: `public/js/employee-options.js`, общий для браузера и серверной проверки групп/грейда.
- Группы хранятся стабильными ID; технологии отдельно в stack. Дальнейший подбор: группы — основной фильтр, технологии — дополнительный критерий, часы — загрузка, назначение подтверждает человек. Сам алгоритм не реализован.
- Прежние нестандартные должности/навыки остаются доступными в редакторе. Автоматического назначения групп и грейдов старым сотрудникам нет.
- Миграция 003: employees.grade/groups и employee_avatars с FK, JPEG BLOB до 128 КиБ. Файл сохраняется в одной транзакции с карточкой; неудачный INSERT откатывает всю правку.
- Браузер принимает JPEG/PNG/WebP до 2 МБ, ограничивает 20 Мп, уменьшает до 256px, конвертирует canvas в JPEG (без исходных метаданных). Сервер проверяет размер, base64 и JPEG-сигнатуру, но не выполняет полное декодирование изображения.
- GET /api/employees/:id/avatar требует тот же вход, что API; файлы не попадают в публичный каталог, имена исходных файлов не сохраняются. Превью использует локальный blob URL, который освобождается.
- Аватары включены в существующую резервную копию SQLite. Перед публикацией нужен backup; старый код с двумя миграциями не откроет БД v3, слепой откат исходников недопустим.
- Повторная попытка Computer Use: RPC sky недоступен; визуальная проверка и реальное декодирование файла браузером не подтверждены.
