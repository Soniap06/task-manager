## Результат и границы

Совместить GitHub App и отдельные проекты Карины с сотрудниками, профилем, входом, событиями GitHub и интерфейсом Софии. Сохранить историю обеих сторон и локальные карточки. Не выполнять merge в main, не публиковать сайт и не создавать внешних задач/веток в habit-tracker.

## Контекст и решения

В Софииных b474b08 и 36fdfa9 сервер и доска заменены: другая SQLite-схема, числовые ID, единый список задач без projectId, Express и отдельный генератор облачного Qwen. У Карины — UUID, JSON v2, идемпотентное создание GitHub-веток и независимые доски. Механическое принятие одной стороны потеряло бы функции другой.

Сохраняются TaskService/ProjectService и рабочие JSON-задачи. Сотрудники и реальные события используют существующий node:sqlite, новая миграция добавляет дедупликацию webhook. Проверяются подпись и ID подключённого репозитория. Новые страницы Софии подключаются к тому же серверу и выбирают проект явно. Доска сохраняет подробности только в диалоге; перенесены поиск, drag-and-drop и выбор исполнителя. Необязательные подписанные сессии закрывают все прикладные API при настройке; пустые настройки сохраняют локальный запуск. Из примера удалены фиксированный пароль и секрет. Профиль не выдаёт Софию за любого вошедшего пользователя. Демонстрационные события/задачи не создаются.

Старые зависимости не нужны: функции адаптированы к встроенным модулям Node.js 24. Прежняя data/task-manager.db не затрагивается; автоматическое приписывание её задач новому репозиторию запрещено. Облачный и локальный Qwen используют общий серверный генератор; отдельный endpoint предпросмотра не сохраняет карточку и не вызывает GitHub.

Незакоммиченные изменения Qwen сохранены в резервном stash перед merge и восстановлены поверх слияния; они остаются вне merge-коммита. Новая модель по-прежнему требует отдельной проверки; интеграция не означает успешную оценку качества Qwen.
