# Управление профилями сотрудников: API

- Дата: 15 ноября 2026.
- Ветка: `r2-employee-management-api`.
- База: `karinalien/main` (`55e090a`).
- Объём по плану команды: хранение и API Софии. Интерфейс редактирования профилей остаётся отдельной задачей.

## Результат

- `POST /api/employees` создаёт профиль со случайным UUID.
- `PATCH /api/employees/:id` частично меняет профиль; ID, привязка пользователя и служебные поля не редактируются.
- Проверяются имя, должность, тип исполнителя, список навыков, доступные часы и адрес аватара. Значения сохраняются в существующей SQLite-таблице `employees`; миграция схемы не нужна.
- `avatar_url` принимает HTTPS-ссылку или локальный путь, чтобы UI карточек мог безопасно отобразить установленный аватар.

## Проверки и ограничения

- Просмотрены изменения и выполнен `git diff --check`.

- Рабочая ветка локальная и не опубликована. Изменения основаны на `55e090a`.
- Роли доступа и отдельные учётные записи не входят в этот объём; доступ соответствует текущей модели общего входа.


## Исправление подключения HTTP — 17 ноября 2026

После обновления до origin/main `8fe5a23` воспроизведено: POST /api/employees и PATCH /api/employees/:id возвращали 405, поскольку методы Workspace не вызывались маршрутизатором. В отдельной ветке `r2-employee-api-routes` маршруты включены в существующий обработчик JSON-изменений. Успех: 201/200 с `{ employee }`; общий вход, Origin, Content-Type и лимит тела сохранены. Новые HTTP-тесты покрывают создание/чтение/частичный PATCH, неверные поля и JSON, размер тела, неизвестный ID, отсутствие входа и чужой/отсутствующий Origin в shared-режиме. Изменения пока локальные, без коммита/push/развёртывания. UI и миграции не входят в исправление.

Проверки исправления: 18/18 HTTP-тестов, полный набор 166/166, `npm run check` (42 JS) и `git diff --check` успешны. Все данные тестов временные, GitHub/LLM используют заглушки.
