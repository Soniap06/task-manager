# Одна доска на двух компьютерах

Состояние на 22 октября 2026: поддержка подготовлена в `codex/shared-board-tailscale`, от `44ca44a`. Tailscale Serve включён; реальный HTTPS, вход и защита проектов проверены с компьютера Карины. Открытие доски на компьютере Софии пока не подтверждено. Изменения профилей в основном checkout остаются отдельно.

## Как устроено

Один процесс Task Manager работает у Карины. SQLite, tasks.json, ключ GitHub App и LM Studio остаются на её компьютере. Оба браузера открывают один HTTPS-адрес Tailscale Serve. София не запускает свою копию через npm start. Карточки обновляются раз в 5 секунд; при открытом редакторе обновление откладывается до его закрытия. Скрытые вкладки не опрашивают сервер. При сбое сети доска сохраняется и запросы повторяются.

Это не синхронизация двух локальных баз и не офлайн-режим. Для работы компьютер Карины должен быть включён и подключён к сети, сервер и Tailscale должны работать. Порт Node.js остаётся привязан к 127.0.0.1.

## Подготовка Tailscale

1. Установить Tailscale с https://tailscale.com/download на обоих компьютерах. Каждый входит под своим аккаунтом, разрешает VPN и включает подключение.
2. Карина в https://login.tailscale.com/admin/machines выбирает свой компьютер и делится именно им с аккаунтом Софии через Share. София принимает приглашение. Если политика сети запрещает sharing, её администратор должен разрешить соответствующий доступ; не открывайте весь компьютер в интернет.
3. Узнать DNS-имя компьютера в списке Machines в Tailscale либо через `tailscale status --json` (поле Self.DNSName). Если на macOS команда не найдена, использовать `/Applications/Tailscale.app/Contents/MacOS/Tailscale status --json`. Из имени убрать завершающую точку и составить `https://computer.tailnet-name.ts.net`. Сначала настроить вход приложения по шагам ниже, затем включать Serve и передавать адрес Софии.

## Настройка приложения у Карины

1. Использовать код с поддержкой `SHARED_ORIGIN`. Перед переключением ветки сохранить незакоммиченные изменения. Не создавать второй сервер для того же DATA_DIR.
2. Остановить прежний Task Manager через Ctrl+C, сделать резервную копию `.data` после остановки сервера (JSON и SQLite вместе).
3. В серверном `.env` заполнить:

   ```dotenv
   SHARED_ORIGIN=https://computer.tailnet-name.ts.net
   DEMO_USERNAME=team
   DEMO_PASSWORD=ваш-непустой-пароль
   SESSION_SECRET=ваш-случайный-секрет-не-короче-32-символов
   ```

   Заменить все примеры своими значениями. Не добавлять `/` в конец SHARED_ORIGIN. При смене SESSION_SECRET прежние сессии перестанут работать. Для генерации случайного секрета можно локально выполнить `node -e 'console.log(require("node:crypto").randomBytes(32).toString("hex"))'`; не присылайте вывод в чат и не сохраняйте его в Git. GitHub App, DATA_DIR и ai.config.json оставить существующими.
4. Выполнить `npm start` из нужного checkout. Если используется worktree, личные `.env`, ai.config.json и `.data` автоматически туда не копируются. Настройте абсолютный DATA_DIR к существующему каталогу и путь ключа, проверьте путь перед запуском; не запускайте два процесса на этих данных.
5. В другом терминале выполнить `tailscale serve 3000` и оставить его работающим (на macOS при отсутствии команды в PATH — `/Applications/Tailscale.app/Contents/MacOS/Tailscale serve 3000`). Если Tailscale предложит включить HTTPS, владелица сети подтверждает это в его интерфейсе. Адрес в выводе команды должен совпасть с SHARED_ORIGIN. Использовать Serve, а не публичный Funnel. Для общей доски открывать именно HTTPS-адрес из SHARED_ORIGIN, включая на компьютере Карины. Прямой http://127.0.0.1:3000 в shared-режиме не подходит для входа: cookie имеет Secure, а Origin проверяется по HTTPS-адресу.
6. София подключает Tailscale, открывает тот же адрес, входит и выбирает тот же проект. Передать ей только адрес и пароль приложения защищённым способом, без .env, SESSION_SECRET и ключа GitHub.

Сейчас вход демонстрационный: один логин для двух браузеров, без индивидуальных прав и аудита действий. При логине team личный профиль сотрудника не выбирается. Отдельные аккаунты и полноценное редактирование карточек — будущий объём. Выход удаляет cookie только в текущем браузере; смена SESSION_SECRET завершает все сессии.

## Проверка вдвоём

Создать согласованную тестовую карточку «Без ИИ», не подтверждая ветку. Во втором браузере выбрать тот же проект: карточка должна появиться в течение 5 секунд. Переместить её между колонками и проверить результат в первом браузере. Открыть редактор: введённый текст не должен пропадать от фонового обновления. После закрытия редактора доска получает изменения. Реальный тест с обоими компьютерами проводится отдельно от автоматических тестов с заглушками.

## Отключение и диагностика

- Остановить foreground-команду Serve через Ctrl+C; при фоновом запуске проверить `tailscale serve status` и использовать `tailscale serve reset` только для отключения всех Serve-настроек этого компьютера.
- Для возврата к прежнему локальному режиму очистить SHARED_ORIGIN и перезапустить приложение. Вход можно оставить включённым. Остановить Serve до отключения защиты приложения.
- Нет соединения: оба устройства Connected, приглашение принято, компьютер Карины не спит; проверить политики Tailscale, вывод Serve и `GET /api/health` по общему адресу.
- 403: адрес браузера и SHARED_ORIGIN должны совпадать в точности; не использовать localhost, IP или другой DNS-псевдоним.
- Ошибка настройки при запуске: заполнить все три поля входа, секрет минимум 32 символа; адрес только HTTPS *.ts.net без пути.
- Потеря данных/разные доски: проверить один сервер, один DATA_DIR и одинаковый projectId. Не копировать поверх рабочих данных файлы другого компьютера.

Источники настройки: [Tailscale Serve](https://tailscale.com/docs/features/tailscale-serve), [команда Serve](https://tailscale.com/docs/reference/tailscale-cli/serve). Приложение не доверяет заголовкам Tailscale/Forwarded как способу входа; доступ к API проверяет собственной сессией.
