5 ноября 2026. Проверено после git fetch --all --prune: в upstream/main один новый коммит 68b2b5b (пять колонок, редактирование подтверждённых карточек и назначений). Наша база — 59c92b6 с незакоммиченными R4/проверками Qwen; рабочее дерево не изменялось при проверке Софии, merge/push не выполнялись.

## Найденные дефекты

1. **P1: удаление `.env.example` ломает настройку чистой копии.** Удалён весь файл `.env.example` (строка 1 прежней версии); `scripts/setup.mjs:6` продолжает копировать его в `.env`. В отдельном снимке upstream/main `npm run setup` воспроизводимо завершается ENOENT до создания конфигов. Нужно вернуть шаблон, он не содержит реальных ключей.
2. **P2: параллельное редактирование затирает изменения другого участника.** `lib/tasks.js:80–100` сохраняет patch без проверки версии; `script.js:385` всегда отправляет старые title и description вместе с изменением исполнителя. Обе участницы открывают карточку; Карина меняет название, София из прежней формы меняет исполнителя и сохраняет — название возвращается к прежнему. Воспроизведено через TaskService с двумя снимками карточки. Нужен expectedRevision/updatedAt и ответ 409 для устаревшей формы, либо согласованная защита от потери обновлений. Одна serial-очередь не решает проблему устаревшего снимка.

Ссылки на проверенный код: [TaskService](https://github.com/Soniap06/task-manager/blob/68b2b5b/lib/tasks.js#L80), [формирование patch](https://github.com/Soniap06/task-manager/blob/68b2b5b/script.js#L385), [setup](https://github.com/Soniap06/task-manager/blob/68b2b5b/scripts/setup.mjs#L6).

## Проверки и совместимость

- Изолированный снимок коммита: npm test 112/112, npm run check — 35 JS и локальные HTML-ресурсы. Для check инициализирован отдельный временный Git-индекс (скрипт перечисляет git ls-files); это не изменение рабочих веток.
- Пять колонок и изменение названия/описания/исполнителя покрыты тестами Софии; запись GitHub при правке не повторяется, вход и Origin-защита нового PATCH сохранены.

Это результат только для закоммиченного R3; незакоммиченные изменения R4 также надо учитывать при реальном объединении. Нельзя принимать любой файл целиком одной стороны: в server.js нужно сохранить одновременно clarify и PATCH, в script.js — интервью и редактор подтверждённой карточки, пять колонок и поле имени ветки.

## Исправление после поручения пользователя

Обе проблемы исправлены в объединённом рабочем дереве: .env.example восстановлен, PATCH требует expectedRevision с 409 для устаревшей формы. Конфликты разрешены с сохранением интервью/веток и всех функций Софии. Добавлены регрессионные проверки свежего setup и его повторяемости, версии при двух редакторах и после открытия хранилища, HTTP/Origin, сохранения текста в конфликтующей форме. Две настоящие вкладки подтвердили защиту от потери правки и загрузку свежей версии. Подробности — [план R1](../plans/R1-five-column-card-edit.md).
