# Запуск и ограничения развёртывания

Объединённая версия использует Node.js 24, встроенные HTTP и SQLite. Express, dotenv и better-sqlite3 из ветки Софии не требуются; установка npm-зависимостей не нужна.

1. Выполнить `npm run setup`, настроить локальный `.env` по README, затем `npm start`.
2. Рабочие карточки и проекты сохраняются в `DATA_DIR/tasks.json`, сотрудники и события — в `DATA_DIR/task-manager.sqlite`. Нужен постоянный диск; сохраняйте резервные копии обоих файлов.
3. Для необязательного входа заполнить все три переменные: DEMO_USERNAME, DEMO_PASSWORD, SESSION_SECRET (не менее 32 случайных символов). По умолчанию все пустые: локальная работа без входа. Частичная настройка закрывает API с ошибкой конфигурации. Для профилей демо-команды логины `karina` и `sofia`.
4. Webhook принимает `POST /api/webhooks/github`, проверяет X-Hub-Signature-256 по GITHUB_WEBHOOK_SECRET и repository.id подключённого проекта, сохраняет push/pull_request/pull_request_review. Повтор delivery ID не добавляет событие. GitHub App для создания веток и webhook — разные направления интеграции.
5. Сервер слушает только 127.0.0.1 и проверяет Host/Origin. GitHub не может отправить webhook на localhost. Публичная публикация и настройка reverse proxy/HTTPS не выполнялись; добавление входа не делает текущую версию готовой к интернет-развёртыванию. GitHub Pages не запускает Node.js.

Не коммитьте `.env`, пароли, ключи, базы и `ai.config.json`. Облачный Qwen можно подключить через общий серверный клиент ИИ: полный Chat Completions endpoint, модель и серверный ключ; отдельный несовместимый генератор не нужен.

Прежняя база Софии `data/task-manager.db` не перезаписывается и автоматически не импортируется: её задачи не содержат подтверждённого GitHub projectId. При наличии такого файла потребуется отдельный перенос с явным сопоставлением проектов. SQLite задач этой версии пока остаётся заготовкой; рабочие карточки не мигрируются скрыто.
