# Task Manager

Учебная канбан-доска с подключаемыми GitHub-проектами и уточнением требований через Qwen. Доска содержит Backlog, To Do, In Progress, Review и Done. После проверки и подтверждения карточки приложение создаёт связанную GitHub-ветку. Встроенный ИИ пока помогает оформить задачу, но не выполняет её код.

Общий сайт: [tm-project.duckdns.org](https://tm-project.duckdns.org/login). Состояние выпуска и ограничения — в [docs/PROJECT.md](docs/PROJECT.md), обслуживание сервера — в [docs/VPS.md](docs/VPS.md).

## Локальный запуск

Нужны Git и Node.js 24 (`nvm use` при наличии nvm). Сборки и внешних npm-зависимостей нет.

```bash
npm run setup
npm run check
npm test
npm start
```

Откройте `http://127.0.0.1:3000` или порт из `.env`. Live Server на 5500 запускает только статические файлы и не заменяет backend. `setup` создаёт `.env` и `ai.config.json` из примеров только при их отсутствии; личные настройки сохраняются.

| Настройка `.env` | Назначение |
| --- | --- |
| `GITHUB_APP_ID` | ID GitHub App |
| `GITHUB_INSTALLATION_ID` | ID установки App |
| `GITHUB_PRIVATE_KEY_PATH` | Путь к RSA PEM; предпочтительно вне проекта |
| `AI_API_KEY` | Необязательный серверный ключ API ИИ |
| `PORT` | По умолчанию 3000 |
| `DATA_DIR` | Каталог данных, по умолчанию `.data` |
| `DEMO_USERNAME`, `DEMO_PASSWORD`, `SESSION_SECRET` | Общий вход; секрет сессии — не менее 32 случайных символов |
| `SHARED_ORIGIN` | Точный HTTPS-origin общего сайта за прокси |

Все три настройки входа пустые — локальный режим без входа. Частичная настройка закрывает API до исправления. Для общего сайта вход обязателен. Это демонстрационный общий аккаунт, а не полноценные пользователи и роли. Сервер слушает loopback; правила Host/Origin нельзя обходить отключением проверки. Настройка HTTPS-прокси описана в [VPS.md](docs/VPS.md).

## Где менять API ИИ

**Корневой `ai.config.json`**: `endpoint` — полный Chat Completions URL с JSON schema, `model` — ID модели, `generation` — параметры, `timeoutMs` — таймаут, `apiKeyEnv` — имя переменной ключа (по умолчанию `AI_API_KEY`). Образец: [ai.config.example.json](ai.config.example.json). Ключ хранится в серверном `.env`, а не в JSON или браузере. После изменения перезапустите Task Manager.

Текущий профиль — `qwen/qwen3.5-9b` в LM Studio, контекст 32768, одна генерация за раз; проверен на Mac с 16 ГБ RAM:

```bash
lms server start
lms load qwen/qwen3.5-9b --context-length 32768 --parallel 1 --identifier qwen/qwen3.5-9b --ttl 7200 --yes
npm run llm:check
```

Пример конфигурации использует `timeoutMs: 300000`: длинная история может не уложиться в прежние 120 секунд. Существующий личный конфиг setup не меняет. Для другого API неподдерживаемые необязательные параметры `top_k` и штрафы можно удалить. Общий клиент — `lib/llm.js`. Старые `LM_STUDIO_ENDPOINT`/`LM_STUDIO_MODEL` в `.env` и личный `ai-api.js` больше не используются; сохранённый личный файл не удаляется.

На VPS Qwen подключён к Mac через закрытый SSH-мост. При выключенном Mac сайт продолжает работать, генерация недоступна. Режим «Без ИИ» позволяет заполнить карточку вручную; при ошибке модели есть явный переход к ручному редактированию.

## Проекты, карточки и ветки

1. На странице «Проекты» обновите список репозиториев App или найдите репозиторий по GitHub-ссылке.
2. Выберите репозиторий и базовую ветку, подключите и откройте доску. Подключение само по себе веток не создаёт.
3. Выберите тип задачи, исполнителя, введите требования и подготовьте карточку. Можно включить «Без ИИ».
4. Новое интервью содержит 9–30 вопросов суммарно, по 3–5 за раунд (последний может содержать 1–2). Следующая пачка строится после ответов на предыдущую. Отправленные пачки доступны только для просмотра; несданный ввод сохраняется в этом браузере.
5. На шаге «Проверьте информацию о задаче» отредактируйте название, описание и предложенную смысловую часть имени ветки. Qwen предлагает английский slug; код добавляет префикс выбранного типа (`feat`, `fix`, `test`, `docs`) и короткий ID, например `feat/add-habit-categories-b89a71bd`.
6. Подтвердите карточку и создание ветки. До этого внешних записей нет. При занятом имени выберите другое. Повтор подтверждения не должен создавать дубликат.

Исходный запрос и ответы хранятся отдельно от описания. Проверяйте описание: модель может упустить требования или придумать лишние условия. Технический фильтр вопросов и одна корректирующая генерация уменьшают ошибки, но не заменяют смысловую проверку человеком. Прежние карточки сохраняют совместимость с режимом 0–3 вопросов и старыми именами веток; существующие ветки не переименовываются.

Проект выбирается отдельно для вкладки; задача остаётся привязана к исходному проекту при переключении. Изменение базовой ветки влияет на новые задачи. Отключение проекта сохраняет историю и не удаляет GitHub-репозиторий или ветки. URL не расширяет права App; пустой репозиторий без первого коммита и архивный репозиторий не подходят.

Подтверждённую карточку можно открыть и изменить название, описание и исполнителя. Параллельная устаревшая правка получает конфликт без перезаписи сохранённой версии; локальный ввод остаётся до явной загрузки свежей карточки. Перенос в Review пока не создаёт PR. Локальный checkout разработчика не переключается.

Рабочий пример — отдельный [habit-tracker](https://github.com/karinalien/habit-tracker). Созданная ветка означает начало задачи, а не готовую реализацию.

## GitHub App

Права: Contents: Read and write и Metadata: Read-only. Установка через Only select repositories; приложение работает с одной установкой App и несколькими доступными ей репозиториями. При отсутствии репозитория измените доступ установки и обновите каталог.

```bash
npm run github:check
```

Проверка читает каталог установки, не создаёт веток и не выводит токены. Для записи используется временный токен конкретного repository ID. PEM, токены, `.env`, `ai.config.json` и `.data` не попадают в Git и не раздаются браузеру.

Webhook `POST /api/webhooks/github` проверяет подпись по `GITHUB_WEBHOOK_SECRET`, repository ID и повтор delivery ID; поддержаны push/pull_request/pull_request_review. Публичная доставка webhook пока не настроена. Для создания веток webhook не требуется.

## Данные и команда

Задачи и проекты — `DATA_DIR/tasks.json`, формат v2, атомарная запись и блокировка второго процесса. Сотрудники, события и дедупликация webhook — `DATA_DIR/task-manager.sqlite`. SQLite инициализируется сервером, отдельно — `npm run db:init`. Таблицы задач/пользователей подготовлены, но рабочие задачи ещё не перенесены в SQLite. [Схема и миграция](docs/DATABASE.md).

Два браузера общего сайта читают одно серверное хранилище; отдельные локальные запуски имеют независимые данные. Сохраняйте копии JSON и SQLite вместе. Старая база Софии `data/task-manager.db` не импортируется автоматически: нужен отдельный перенос с явным сопоставлением GitHub-проектов.

Доступны страницы сотрудников, профиля и событий; ёмкость показана в часах на спринт, назначенные задачи — отдельным количеством. Карина, София и Qwen — начальные демонстрационные записи; Qwen как исполнитель ещё не пишет код. Нет регистрации, ролей, редактирования профилей и планирования спринта.

## Проверки и инструкции

- `npm run check` — синтаксис JS и ресурсы HTML.
- `npm test` — поведение с заглушками GitHub/LLM, без внешних записей.
- `npm run llm:check` — реальная модель, без сохранения карточек/веток; смысл результата проверяется человеком. Свой запрос: `npm run llm:check -- "Описание задачи"`.
- [AGENTS.md](AGENTS.md) — инструкции агенту; [WORKFLOW.md](docs/WORKFLOW.md) — ветки, PR и передача работы.
- [PROJECT.md](docs/PROJECT.md) — текущие возможности; [REQUIREMENTS.md](docs/REQUIREMENTS.md) — ТЗ и оставшиеся задачи.
- [Архив](docs/archive/README.md) — история выполненных этапов; [шаблон](docs/plans/TEMPLATE.md) — новые планы.
